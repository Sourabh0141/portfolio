# Sourabh Sharma — Portfolio

Personal portfolio built with [Astro](https://astro.build) (static output) and deployed to
**Cloudflare Pages** at <https://sourabh.pages.dev>. There is no CMS or admin UI: all content
lives in this repository and goes live when it lands on `main`.

## Stack

- **Astro 7**, fully static, zero client framework. A single small script adds the mobile menu,
  theme toggle, scroll-spy, copy button and reveal-on-scroll — the page works without it.
- **TypeScript** (strictest Astro preset), **Zod**-validated content collections.
- Plain scoped CSS with design tokens (`src/styles/global.css`); dark-first with a light theme.
- Self-hosted fonts via the Astro Fonts API (Space Grotesk, Inter, JetBrains Mono).
- Content-Security-Policy generated by Astro (hash-based, no `unsafe-inline`), plus
  `public/_headers` for response headers.
- ESLint (with `jsx-a11y` rules) and Prettier; GitHub Actions for CI/CD.

## Project structure

```
src/
  components/        Reusable UI (header, footer, cards, diagrams, icons)
    sections/        One component per page section
  content/
    projects/*.yaml  Project case studies (validated by src/content.config.ts)
    experience/*.yaml
  data/site.ts       Profile, links, skills, education, SEO strings
  layouts/           Base HTML shell
  pages/             index, 404, robots.txt
  scripts/main.ts    Progressive-enhancement behaviour
  styles/global.css  Tokens + base styles
  site.config.ts     SITE_URL (single source of truth)
public/              Static assets: favicon, OG image, _headers, résumé PDF
scripts/             One-off tooling (OG image generator)
docs/reference/      Original design reference and Flare technical summary
```

## Commands

| Command            | What it does                                                   |
| ------------------ | -------------------------------------------------------------- |
| `npm run dev`      | Dev server at http://localhost:4321                            |
| `npm run build`    | Production build to `dist/`                                    |
| `npm run preview`  | Serve the production build locally                             |
| `npm run validate` | Prettier check, ESLint, `astro check` and a build              |
| `npm run format`   | Format everything with Prettier                                |
| `npm run og`       | Re-render `public/og.png` and the touch icon (needs a browser) |
| `npm run deploy`   | Build and deploy from your machine (needs `wrangler login`)    |

Requires Node ≥ 22.12 (`.nvmrc` pins 22).

## Updating content

- **Profile, links, skills, education, SEO text:** `src/data/site.ts`
- **Projects:** add or edit a file in `src/content/projects/` (the schema in
  `src/content.config.ts` tells you the required fields; the build fails on mistakes).
  `order` controls position and `featured: true` gives a project the large card.
- **Experience:** `src/content/experience/*.yaml` (`end` omitted = current role).
- **Résumé:** replace `public/resume/Sourabh-Sharma-Resume.pdf` and keep the file name. Git
  history keeps every previous version; the PDF is served with revalidation so a new deploy is
  picked up immediately.
- **Social preview image:** edit `scripts/og-template.html`, then `npm run og`.

## Deployment

Pushing to `main` runs `.github/workflows/ci.yml`: format check → lint → type check → build →
deploy `dist/` to the Cloudflare Pages project `sourabh`. Pull requests run the checks only.

One-time setup:

1. Create the Pages project (name = the subdomain you want):
   `npx wrangler login` then
   `npx wrangler pages project create sourabh --production-branch=main`
2. In Cloudflare, create an **API token** with _Account → Cloudflare Pages → Edit_ and note your
   **Account ID** (Workers & Pages overview page).
3. In GitHub → Settings → Secrets and variables → Actions, add the repository secrets
   `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
4. Push to `main`.

If `sourabh` turns out to be taken, choose another project name and update it in **three**
places: `SITE_URL` in `src/site.config.ts`, `PAGES_PROJECT` (and the environment URL) in
`.github/workflows/ci.yml`, and the `deploy` script in `package.json`. Then run `npm run og`
so the preview image shows the right address.

No environment variables are needed at build or runtime, and no secrets are used in the site
code. The only secrets are the two CI credentials above.
